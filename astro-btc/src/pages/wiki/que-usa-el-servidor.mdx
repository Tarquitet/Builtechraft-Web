En Builtechcraft creemos en la transparencia total. Aquí te explicamos **cómo controlamos las modificaciones** y los ajustes que hacen funcionar el servidor.

## 🔄 Control de actualizaciones

Actualizar un servidor técnico no es tan simple como pulsar un botón. Mantenemos un **Panel de Control de Actualizaciones** en Google Sheets que monitorea todo:

<WikiCallout type="info" title="Tres reglas de oro">

1. **Estado de cada mod esencial** con indicador de compatibilidad con la nueva versión de Minecraft
2. **Medidor de progreso automático** — si faltan mods críticos, el panel marca "NO" en rojo
3. **Seguridad ante todo** — jamás actualizamos si un mod de seguridad u optimización no está listo; preferimos esperar a corromper el mapa

</WikiCallout>

## ⚙️ Por qué usamos Fabric

En Builtechcraft decidimos un servidor basado en **Mods (Fabric)** en lugar de Plugins (Spigot, Paper) por dos razones:

<WikiTable
  headers={['Criterio', 'Fabric (lo que usamos)', 'Plugins (lo que no usamos)']}
  rows={[
    ['Velocidad de actualizaciones', { text: 'Días', tone: 'good' }, { text: 'Meses', tone: 'bad' }],
    ['Respeto al vanilla', { text: '100% fiel', tone: 'good' }, { text: 'Modifica código base', tone: 'bad' }],
    [
      'Mecánicas técnicas (granjas, redstone)',
      { text: 'Intactas', tone: 'good' },
      { text: 'Rompes granjas', tone: 'bad' },
    ],
    ['Experiencia ideal para ingeniería', { text: '✓ Sí', tone: 'good' }, { text: '✗ No', tone: 'bad' }],
  ]}
/>

<WikiCallout type="ok" title="Filosofía">

Fabric respeta al 100% las mecánicas originales del juego. Esto lo hace ideal para jugadores técnicos que quieren construir granjas, sistemas de redstone y proyectos de ingeniería.

</WikiCallout>
